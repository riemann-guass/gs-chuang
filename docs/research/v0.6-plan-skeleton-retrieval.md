# v0.6：版本化计划 / 骨架 / 检索 —— 按 Numina-Lean-Agent 的做法重做

- 日期：2026-10-24
- 决策：**计划保留，骨架与检索默认关闭**（见 ADR-0012）
- 记录：`runs/v06-B6.jsonl`、`runs/v06-V1.jsonl`、`runs/v06-V2.jsonl`

## 背景

v0.5 的 Critic 只把一句话塞进 prompt，干净基线 125/244，Critic 在 100 题上
−2（修好"建议没下传"后 +2，但 token +123%）。读了
[Numina-Lean-Agent](https://github.com/project-numina/numina-lean-agent) 的
prompt 与工具实现后，发现差距不在"要不要加角色"，而在三件具体的事：

1. 它们有 `informal_<lemma>.md`：**版本化的证明计划**，attempt 0 生成、
   在 attempt 2/4/8/16/32 带着失败历史重写；
2. 它们允许 `sorry`，只留**最小卡点**，所以部分进展可积累；
3. 它们把检索（LeanExplore/Loogle）当主工具，补"不知道引理叫什么"的定位 gap。

## 实现

| 能力 | 实现 | 开关 |
|---|---|---|
| 计划 | `roles.planner_prompt/parse_plan`；`pipeline.stage_plan`；第 0 轮生成，`failed_rounds ∈ {2,4,8}` 重写 | `--plan` |
| 骨架 | `worker.count_sorries` + `WorkerResult.compiles`；骨架可编译但**不算通过**，只记 `best_skeleton` | `--skeleton` |
| 检索 | `harness/retrieval.py`：Loogle 公开 JSON 接口（无需 key），磁盘缓存，失败降级为空 | `--retrieval` |

## 结果（同一 100 题等距子集，全部 `--judge worker`）

| 组 | 内容 | pass | token in | 相对 |
|---|---|---:|---:|---|
| P0 | 2 轮（v0.5 基线） | 54/100 | 71,149 | — |
| **B6** | 6 轮，无新功能 | **52/100** | 337,068 | 加轮数**没用**（第 4–6 轮 0 通过） |
| **V1** | 6 轮 + 计划 | **60/100** | 562,835 | **比 B6 +8 题**（token +67%） |
| **V2** | V1 + 骨架 + 检索 | **61/100** | 587,788 | 比 V1 +1（噪声内） |

**计划是这一轮唯一确定的收益**：+8 题，且增益主要发生在第 1 轮（30 vs 25）——
说明"先有计划再写 tactic"确实改变了第一次尝试的质量。

**骨架一个都没生效**：100 题里 `best_skeleton=0`。查了实际失败样本，
模型给出的"骨架"大多在 `sorry` 之前就编译失败（`compiles=False`），
也就是说它**写不出能编译的前缀**——这和"表达 gap"的判断一致，不是接口问题。
（第一版还有个 bug：系统提示写着"不要使用 sorry"，与骨架指令冲突；已修并加了回归测试，
但修完仍然 0，说明不是提示词的问题。）

**检索命中 102 条，但 Δ 只有 +1**：Loogle 能查到引理，但 Flash 并不会因为
"给了候选引理名"就证出来——它缺的是**怎么用**，不是"叫什么"。

## 结论

1. **计划保留**（`--plan`），这是目前性价比最高的单项改进：+8 题 / +67% token。
2. **检索默认关闭**：在这个模型上不划算（+1 题，多 80 次网络调用）。
3. **骨架默认关闭**：接口保留，但 Flash 产不出可编译的骨架；
   要让它生效，得先解决"写出一段能编译的前缀"，那是另一个问题。
4. **加轮数没用**：6 轮 vs 2 轮反而 −2，且第 4 轮之后基本不再得分。
   预算应该花在"更好的信息"上，不是"更多的重试"。

## 下一步

- 计划已经证明有效，下一步应该优化**计划的质量与成本**：
  只在第 1 次失败后重写一次（而不是 2/4/8 三次），看能否保住收益、砍掉一半 token。
- 检索可以改成"只在 `missing_lemma` 标签出现时查"（现在是第二次失败就查），
  减少无效调用。
- 骨架要等模型能写出可编译前缀后再评估。
