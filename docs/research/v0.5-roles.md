# v0.5：三角色（Prover / Critic / Strategist）的 A/B 记录

- 日期：2026-10-24
- 决策：**Critic 与 Strategist 均不加入**（见 ADR-0011）
- 记录：`runs/v0.5-baseline.jsonl`、`runs/v0.5-critic100.jsonl`、`runs/strategy-probe.jsonl`

## 协议

- 数据：miniF2F Valid，244 题；A/B 用**同一个 100 题等距子集**（`--sample 100`，确定性）
- 管线：L0 → 确定性补救 → L1×2，`--judge worker`（L1 用常驻 worker 判定，
  结束后对通过者批量终审）
- 模型：`deepseek-flash`，`thinking: disabled`，temperature 0.7
- 判定：pass@1 + token + 墙钟；门槛先定（Critic Δ ≥ +2 且 token ≤ +40%）

## 结果

### P0 干净基线（全量 244）

**125/244 = 51.23%**（L0 59 + 模型 66），token in 179,710 / out 99,511。

> 之前 v0.1 的 121/244 是**下界**：一块 60 题的 L1 批次撞上 1800 s 超时被截断。
> 换成 worker 判定后不再有批量编译的 30 分钟块，数字才稳定下来。

### P1 +Critic（100 题子集）

| | 基线 | +Critic | Δ |
|---|---|---|---|
| pass | **54/100** | **52/100** | **−2** |
| token in | 71,149 | 120,351 | **+69%** |
| token out | 40,292 | 45,662 | +13% |
| 墙钟 | 1000 s | 1140 s | +14% |

Critic 的标签分布（两轮合计）：`unsolved` 73、`syntax` 9、`missing_lemma` 6、
`wrong_strategy` 3、`type_mismatch` 7、`needs_induction` 1、`other` 2。

**它基本只会说"你没证完"**——这是 Prover 早就从诊断里知道的信息，
而真正能触发路由的 `wrong_strategy` / `needs_induction` 几乎不出现。

### P2-pre 策略探针（244 题）

| 指标 | 值 |
|---|---|
| 可评估（已解出、能打弱标签） | 125 |
| 模型 top-1 | 108 = 86.4% |
| **多数类基线（全猜 direct）** | **87.2%** |
| 相对基线 | **−0.8%** |

**结论：模型没有策略信号**，因此跳过 Strategist——不是"效果不确定"，
而是"做它的前提不成立"。

## 三个基础设施事故（都发生在做基线时）

| # | 事故 | 影响 | 修法 |
|---|---|---|---|
| 1 | worker 把定理参数统一改名成 `arg` | 引用 `a`/`h₀` 的模型证明全报 `Unknown identifier`，基线 121→61 | `withLocalDecl name bi …` 保留原名；新增 `scripts/worker_regression.py` 复判**模型写过的**证明 |
| 2 | 终审超时把已验证的题降级成 `error` | 一块 60 题撞 1800 s，60 道已通过的题被抹掉，基线 121→58 | `keep_on_timeout`：超时只记 `audit_timeout`，保留 worker 判定；终审改 40 题/块、600 s 上限 |
| 3 | `lake env lean` 被 kill 时留下孤儿 `lean`（3+ GB） | 两个 lean 抢 CPU，单次判定从 0.2 s 退化到几十秒 | 改为**直接 spawn `lean.exe`**（自己拼 `LEAN_PATH`），`proc.pid` 就是 lean |

**共同教训**：在比较"加角色有没有用"之前，必须先确认**测量工具本身没坏**。
这三个坑里有两个会让结论完全反转，而且都不会以报错的形式出现。

## 下一步

- Critic/Strategist 的代码保留（`--critic` / `--strategist`，默认关），
  但**不再作为研究方向**。
- M4 检索（LeanSearch）是剩下的唯一"工程能补"的 gap（定位 gap）；
  做之前同样先定门槛、先测基线。
